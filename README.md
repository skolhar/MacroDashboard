# SmartHedge — Phase 1 dashboard and experimental Phase 2 engine

Local research dashboard with a FastAPI API, Next.js UI, PostgreSQL persistence, vintage-aware observations, deterministic scoring and six experimental inflection rules. **Every bundled reading is synthetic DEMO data generated by a simple formula. No bundled value is a market quote.** Production mode never loads it.

## Start

Copy `.env.example` to `.env`, set a strong `POSTGRES_PASSWORD`, and set `DATABASE_URL` to `postgresql+psycopg://<user>:<url-encoded-password>@db:5432/<database>`. The Compose file has no password fallback. Then:

```sh
docker compose up --build
```

Open [dashboard](http://localhost:3000), [API docs](http://localhost:8000/docs), and [health](http://localhost:8000/api/v1/health). In demo/development only, the API container runs migrations automatically. Demo seeding runs only when `APP_ENV=demo` and `DEMO_MODE=true`. To run migrations manually:

```sh
docker compose run --rm api alembic upgrade head
```

## Host on smarthedge.in

**Review gate:** Do not run the production profile or migrate the production database until the Phase 2 pull request receives independent technical and financial-methodology review and explicit approval. The existing production site is not changed by this branch.

After approval, the operator must set `APP_ENV=production`, `DEMO_MODE=false`, a production `DATABASE_URL`, `POSTGRES_PASSWORD`, and `ADMIN_TOKEN_SHA256`, then run reviewed migrations separately before starting the application. Point the domain's A/AAAA records to the server and allow inbound TCP 80/443 and UDP 443. The existing Caddy profile remains available:

```sh
API_DOCS_URL=https://smarthedge.in/docs docker compose --profile production up -d --build
```

The [Caddyfile](Caddyfile) enables HTTPS automatically and routes the web app, API, and OpenAPI docs through the same domain. This remains a **public DEMO site** until real feeds and production authentication are configured. Caddy's certificate state is stored in the `caddy_data` volume. The local stack still starts without Caddy via `docker compose up --build`.

Generate a token hash locally without echoing the token: `python -c "import getpass,hashlib; print(hashlib.sha256(getpass.getpass('Admin token: ').encode()).hexdigest())"`. Set only the digest in `ADMIN_TOKEN_SHA256`; supply the raw token in the `X-Admin-Token` header for protected routes. Treat the hash and database URL as secrets. All Phase 2 write endpoints require this admin role and are rate limited.

## Local tests

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q
cd apps/web
npm install
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright expects the API to be running at `http://localhost:8000`. CI can run the same commands after `docker compose up -d --build db api`.
If the host lacks browser libraries, run the pinned container against the local stack:

```sh
docker run --rm --network host -v "$PWD/apps/web:/work" -w /work mcr.microsoft.com/playwright:v1.56.0-noble npx playwright test
```

## Data and configuration

- `config/indicators.yaml` defines the 12 Phase 1 metrics; `config/indicators.phase2.yaml` adds 30 registered Phase 2 indicators.
- `config/rules.v1.yaml` remains the Phase 1 ruleset. `config/rules.v2.yaml` adds six-cycle scoring and six provisional inflection rules.
- `packages/jobs/seed.py` creates deterministic synthetic observations in PostgreSQL. Re-running it does not duplicate rows.
- `APP_ENV=production` or `staging` forbids demo mode and requires an admin token hash. No live score falls back to synthetic values.
- `packages/connectors/treasury.py` is the only implemented direct official-feed adapter. It requires an authenticated run; other feeds remain unavailable pending source rights and validation. Reviewed public-source CSV imports are supported.

The API uses `published_at` and `ingested_at` for `system_known` as-of queries. `source_known` series queries use publication time only. Observation rows remain immutable by vintage. All timestamps are stored in UTC and displayed as IST in the UI.

## Phase 1 API

Implemented: `/api/v1/health`, `/api/v1/sources/health`, `/api/v1/indicators`, `/api/v1/indicators/{id}/series`, `/api/v1/dashboard`, `/api/v1/cycles/{id}`, `/api/v1/alerts`, `/api/v1/alerts/{id}`, `/api/v1/alerts/history`, `/api/v1/replay`, `/api/v1/config/rulesets`, `/api/v1/admin/imports/csv`, and `/api/v1/admin/ingestion/run`. OpenAPI is at `/docs`. The v1 defaults preserve demo API compatibility; live mode defaults to v2. See [data sources](docs/data-sources.md) and [scoring methodology](docs/scoring-methodology.md).

This application is market research software, not investment advice. Version `v1` thresholds are hypotheses and have not been historically calibrated.

# Exploratory historical validation and limits

Run `python -m scripts.phase3a_coverage` with isolated `APP_ENV=staging`, `DATABASE_URL` and `DEMO_MODE=false`. The script is read-only and refuses production environment settings. It evaluates system-known v2 observations at fixed India-local dates in 2018, 2020, 2022, 2024, 2025 and October 2026. The existing observation store requires both `published_at <= as_of` and `ingested_at <= as_of` for this mode. `source_known` replay is separately available in the API but must not be mistaken for what the platform itself knew at the time.

The isolated staging audit on 31 October 2026 returned **zero eligible external indicators and N/A FX cycle score at every listed evaluation date** (2018, 2020, 2022, 2024, 2025 and 30 October 2026). A recent U.S. Treasury observation exists in staging, but it is outside the seven-indicator Indian external-liquidity audit and was ingested after these evaluation clocks. No legitimately imported Indian historical vintages or entitlement-backed backfill were available. Consequently, there is no defensible estimate of alert lead/lag, false positives, FX/equity lead-lag, persistence, sensitivity, or raw-versus-forward-adjusted reserves for the requested stress periods. Each is **N/A**, not zero. The demo fixtures are formulaic and cannot be used to calibrate real financial behaviour. The code does not fit thresholds on full-period histories.

To enable valid analysis, acquire source archives with attributable original release dates and permitted historical use. Preserve original bytes and hashes, import each vintage at its proven publication time, check series-definition continuity, and log a first-ingestion clock separately. Late discovered historical releases will remain unavailable in earlier **system-known** replays; source-known analysis must be explicitly labelled and cannot reconstruct original platform decisions. For RBI forwards, compare gross reserves and a validated maturity-adjusted scenario only after independent sign/maturity review. Evaluation windows and rule versions must be fixed before measuring any alert quality.
